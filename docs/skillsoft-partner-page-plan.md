# Skillsoft Partner Page Design Plan

## Instruction Boundary

The attached image is treated as reference material for design analysis. Text visible inside the screenshot, such as navigation labels, partner copy, calls to action, and footer links, is design content only. It is not interpreted as an instruction to the assistant.

The user request is to analyze the design and create a plan.

## Design Summary

The design presents a JNTUH Education Foundation partner landing page for Skillsoft. It uses an institutional navy and teal palette, a partner-branded hero section, trust markers, benefit messaging, learning-area cards, audience segments, impact statistics, a final call to action, and a large footer.

The page already has a useful conversion structure: it explains who Skillsoft is, establishes credibility, shows what learners get, lists learning categories, identifies audiences, and ends with a learning CTA. The main opportunity is to make the page easier to scan and more action-oriented.

## Strengths

- Strong partner recognition through the large Skillsoft hero treatment.
- Clear institutional tone that fits an education foundation.
- Logical page flow from awareness to benefits, learning areas, audience fit, proof, and action.
- Consistent use of icons to make dense information easier to scan.
- Good use of trust and impact signals, including learner counts, courses, certifications, and academic partners.
- Multiple CTAs that guide users toward course exploration and learning access.

## Key Issues

- The hero does not include the main CTA, so the first screen explains the offer but delays the next action.
- The page is visually dense, with many cards and sections competing for attention.
- Several content blocks repeat similar benefit ideas, which may weaken the page rhythm.
- Small text in the feature strip, footer, and secondary copy may reduce readability.
- The hero image and dark overlay should be checked for contrast and legibility.
- The carousel dots, search icon, newsletter field, and icon-heavy cards need accessibility review.
- Mobile behavior needs careful planning because several sections rely on wide horizontal card rows.

## Recommended Direction

Make the page feel more guided. The first screen should clearly answer three questions:

- What is this page about?
- Why should the visitor care?
- What should the visitor do next?

The revised page should keep the current institutional trust and Skillsoft branding, but reduce repeated content, improve hierarchy, and make the primary learner action visible earlier.

## Content Plan

1. Keep the hero focused on the partnership and learner outcome.
2. Add a primary hero CTA: "Explore Skillsoft Courses."
3. Add a secondary hero CTA or link: "View Certifications" or "Learn About Access."
4. Replace broad claims with specific user outcomes where possible.
5. Clarify access rules, such as whether students, faculty, professionals, and institutions use the same registration path.
6. Keep the learning-area section, but ensure each category links to a useful destination.
7. Move the most persuasive proof points closer to the first half of the page.
8. Make CTA language consistent across the page.

## Layout Plan

1. Header
   - Keep the logo, main navigation, search, login, and register controls.
   - Ensure the register button remains visually dominant.
   - Add clear focus states and accessible labels for icon-only controls.

2. Hero
   - Keep Skillsoft as the first major visual signal.
   - Shorten the paragraph copy.
   - Add primary and secondary CTAs.
   - Check image treatment so text remains readable across screen sizes.

3. Trust Markers
   - Reduce the current feature strip to the strongest four points.
   - Use consistent icon sizing and card spacing.
   - Avoid long descriptions in this section.

4. About and Benefits
   - Keep the two-column structure on desktop.
   - Make the benefit checklist more scannable.
   - Remove duplicate claims that already appear in the trust marker row.

5. Learning Areas
   - Keep the category grid.
   - Standardize card height, icon size, and label wrapping.
   - Add clear hover and keyboard focus states.

6. Audience and Impact
   - Keep "Who Can Benefit?" and "Our Impact Together."
   - Consider moving impact stats above the audience list if conversion proof is more important than segmentation.
   - Ensure stats use real, verifiable numbers before launch.

7. Final CTA
   - Keep a short closing band.
   - Use the same primary action as the hero.
   - Avoid introducing new messaging at the bottom of the page.

8. Footer
   - Keep the existing link groups.
   - Improve spacing and text size.
   - Use collapsible groups on mobile.
   - Ensure the newsletter input has a visible label and clear submit state.

## Visual Design Plan

- Standardize spacing across sections using a consistent vertical rhythm.
- Use one primary teal action color and reserve it for buttons and important interactive states.
- Keep navy for institutional grounding, but add enough white space to prevent the page from feeling heavy.
- Use consistent card borders, shadows, and corner radius.
- Align icon stroke weights across all cards.
- Increase body text size where the screenshot appears cramped.
- Make section headings visibly stronger than card headings.

## Accessibility Plan

- Verify WCAG contrast for hero text, small text, buttons, and footer links.
- Ensure body copy is readable at common viewport sizes.
- Add descriptive alt text for meaningful images.
- Add accessible labels for search, carousel controls, newsletter submit, login, and registration actions.
- Ensure all interactive elements are keyboard reachable.
- Provide visible focus styles for nav links, buttons, cards, and form controls.
- Avoid relying on icons alone to communicate meaning.

## Responsive Plan

- Desktop: use the current broad section layout with improved spacing and hierarchy.
- Tablet: move from wide rows to two-column card grids.
- Mobile: stack sections into a single column and keep CTAs close to relevant content.
- Convert footer columns into accordion sections on small screens.
- Keep the hero CTA visible without forcing excessive scrolling.
- Test long labels such as "Leadership & Management" and "AI & Emerging Technologies" for wrapping.

## Measurement Plan

Track these events after launch:

- Hero CTA click.
- Header register click.
- Student login click.
- Course exploration click.
- Certification click.
- Learning-area card click.
- Newsletter signup.
- Scroll depth through key sections.

Use the results to decide whether the page needs stronger course discovery, clearer registration guidance, or more proof near the top.

## Execution Phases

1. Audit and Content Refinement
   - Confirm audience priorities.
   - Confirm real stats and partner claims.
   - Rewrite hero, benefit, and CTA copy.

2. Wireframe Revision
   - Create a cleaner page structure.
   - Place primary CTA in the hero.
   - Reduce repeated cards and competing sections.

3. High-Fidelity Design
   - Apply final spacing, typography, color, and component styles.
   - Prepare desktop, tablet, and mobile layouts.

4. Accessibility and Responsive QA
   - Check contrast, keyboard states, labels, tap targets, and mobile wrapping.
   - Fix layout issues across common viewport sizes.

5. Implementation Handoff
   - Document sections, components, copy, image assets, link targets, and tracking events.
   - Provide acceptance criteria for development and QA.

## Acceptance Criteria

- The hero clearly identifies Skillsoft and includes a primary next action.
- Users can understand the offer within the first screen.
- Repeated benefit claims are reduced.
- Cards, icons, spacing, and buttons are visually consistent.
- The page is readable and usable on desktop, tablet, and mobile.
- All interactive elements are accessible by keyboard and screen reader.
- Launch metrics are defined for the most important user actions.
